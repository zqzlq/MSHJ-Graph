## 1. 赛题解读与项目定位

### 1.1 赛题背景

本项目对应赛题 **XH-202621「多源异构数据驱动岗位和能力图谱构建与动态演化分析研究」**，属于数字经济新一代信息技术赛道。赛题要求参赛团队针对当前就业市场供需匹配不精准、岗位需求动态变化等痛点，研发一套可展示、可验证的岗位能力图谱与智能分析系统。

### 1.2 赛题核心要求

| 要求维度 | 具体内容 | 当前完成状态 |
|---------|---------|------------|
| 多源异构数据采集 | 从招聘平台、行业报告、企业 JD、社交数据等多渠道采集岗位信息 | 样例数据内置，含多源 JD 记录 |
| 文本预处理与清洗 | 对不同格式数据进行标准化处理，降低噪声 | 基于正则和分句的解析管道 |
| 岗位信息智能提取 | 从非结构化文本中提取岗位名称、技能、职责、学历等结构化信息 | 技能词典匹配 + 证据片段抽取 |
| 岗位聚类与新岗位发现 | 聚类分析识别新兴岗位类别 | 基于新兴信号关键词的置信度评分 |
| 动态演化分析 | 分析岗位需求的时间序列变化 | 按 JD 批次对比技能新增/删除/增强 |
| 幻觉防控 | 保证抽取结果可验证、有据可查 | 技能词典归一化 + 证据片段保留 |
| 能力图谱构建 | 将岗位、技能、场景构建为知识图谱 | NetworkX 图结构 + SVG 可视化 |
| 人岗匹配与培养建议 | 匹配评估 + 学习路径输出 | 匹配评分 + 缺口分析 + 学习路径 |

### 1.3 项目定位

本项目是一个 **可运行 MVP（最小可行产品）**，覆盖赛题核心链路的完整闭环：

```
多源 JD 数据导入 → 文本解析清洗 → 技能/职责/场景提取 → 岗位能力图谱构建
                                                        ↓
                                          新岗位发现 + 既有岗位能力更新
                                                        ↓
                                          简历解析 → 人岗匹配 → 学习路径建议
```

MVP 定位为演示级系统，数据量为样例级别，解析算法以可解释的规则引擎为主，后续可扩展为大模型驱动的全量系统。

### 2.3 数据流

系统的核心数据流分为三条主线：

**主线一：岗位能力图谱构建**
```
jobs.json → database.py (SQLite 导入)
  → repository.py (查询)
    → graph.py (NetworkX 构建)
      → /api/graph (REST 响应)
        → main.tsx (SVG 渲染)
```

**主线二：岗位动态演化分析**
```
jobs.json (jd_records) → repository.py
  → parser.py (技能抽取)
    → analysis.py (批次对比: 新增/删除/增强)
      → /api/updates/{job_id}
        → main.tsx (时间线展示)
```

**主线三：人岗匹配与学习路径**
```
简历文本 → parser.py (解析: 技能、项目、年限)
  → analysis.py (匹配: 必备覆盖、加分覆盖、缺口)
    → taxonomy.py (学习路径生成)
      → /api/match
        → main.tsx (评分环、进度条、学习路径)
```

## 3. 技术栈与选型依据

### 3.1 后端技术栈

| 技术 | 版本 | 用途 | 选型理由 |
|-----|------|------|---------|
| Python | 3.10+ | 主语言 | 生态丰富，NLP/图计算库成熟 |
| FastAPI | 0.136.x | Web 框架 | 异步支持、自动 OpenAPI 文档、Pydantic 集成 |
| Uvicorn | 0.46.x | ASGI 服务器 | 高性能、支持热重载 |
| SQLite | 内置 | 数据存储 | 零配置、文件级数据库，适合 MVP |
| NetworkX | 3.6.x | 图谱构建 | 纯 Python 图计算库，支持节点/边属性、密度计算 |
| Pydantic | 2.13.x | 数据校验 | 类型安全的请求/响应模型 |
| pytest | 9.0.x | 测试框架 | 简洁的断言语法、fixture 支持 |
| httpx | 0.28.x | HTTP 客户端 | 测试用异步 HTTP 客户端 |

### 3.2 前端技术栈

| 技术 | 版本 | 用途 | 选型理由 |
|-----|------|------|---------|
| React | latest | UI 框架 | 组件化开发、Hooks 状态管理 |
| TypeScript | latest | 类型系统 | 编译期类型检查，减少运行时错误 |
| Vite | 8.x | 构建工具 | 极速 HMR、开箱即用的 TS 支持 |
| lucide-react | latest | 图标库 | 轻量、Tree-shakable、图标丰富 |
| SVG (原生) | - | 图谱渲染 | 零依赖、DOM 级交互、适合节点数 <100 的场景 |

### 3.3 为什么不用大模型 / 向量数据库

MVP 阶段采用规则引擎 + 技能词典的方案，原因：

1. **可解释性**：每个技能抽取结果都能追溯到具体的匹配别名和原文证据片段
2. **确定性**：相同输入必然产生相同输出，便于测试和评审验证
3. **零外部依赖**：不需要 API Key、不需要网络访问大模型服务
4. **可扩展性**：skill taxonomy 以 JSON 字典维护，后续可无缝替换为 LLM 抽取

## 5. 后端服务设计

### 5.1 API 路由总览

| 方法 | 路径 | 功能 | 请求体 | 响应 |
|-----|------|------|--------|------|
| GET | `/health` | 健康检查 | - | `{"status": "ok"}` |
| POST | `/api/init` | 重置并初始化数据 | - | `{"status": "initialized"}` |
| GET | `/api/dashboard` | 首页仪表盘数据 | - | 岗位数、JD 数、简历数、图谱指标、岗位列表 |
| GET | `/api/jobs` | 岗位列表 | - | `Job[]` |
| GET | `/api/jobs/{job_id}` | 岗位详情 | - | 岗位信息 + 关联 JD 记录 |
| GET | `/api/graph` | 能力图谱 | - | 节点列表、边列表、图指标 |
| GET | `/api/discover` | 新岗位发现 | - | 候选岗位列表（按置信度降序） |
| GET | `/api/updates/{job_id}` | 岗位能力更新 | - | 新增/删除/增强技能对比 |

### 5.2 服务层模块职责

#### `services/taxonomy.py` — 技能词典

这是整个系统的知识基础，定义了：

- **SKILL_ALIASES**：25 个标准技能点及其别名映射。例如 `"RAG"` 对应 `["RAG", "检索增强", "知识库"]`。用于将 JD/简历中的自然语言表述归一化为标准技能名称。
- **SKILL_CATEGORY**：技能到类别的映射（编程语言、后端框架、数据存储、大模型应用、架构能力、云原生、工程质量、知识工程、接口能力、开发工具）。
- **LEARNING_PATHS**：6 个技能的分步学习路径。用于人岗匹配后输出可执行的补齐建议。
- **normalize_skill()**：技能归一化函数，支持大小写不敏感匹配。
- **all_skills()**：返回所有标准技能列表。

#### `services/parser.py` — 文本解析引擎

核心函数：

- **`extract_skills(text)`**：遍历 SKILL_ALIASES，对输入文本做大小写不敏感匹配。对每个命中技能，提取最多 3 条证据句子（包含该技能别名的原文句子）。计算置信度：`min(0.99, 0.72 + 0.08 * 证据数 + 0.04 * 命中别名数)`。
- **`parse_jd(text, title)`**：在技能抽取基础上，额外提取职责句子（含"负责/设计/构建/开发/优化/落地"等关键词）和行业场景（智能客服、企业知识助手等预定义场景词）。
- **`parse_resume(text)`**：在技能抽取基础上，提取项目经验句子和工作年限（正则匹配 `(\d+)\s*年`）。

#### `services/analysis.py` — 分析服务

核心函数：

- **`discover_emerging_jobs()`**：新岗位发现算法。定义 7 个新兴技术信号（Agent、RAG、工具调用、多智能体、大模型、向量数据库、模型评测），对每个岗位的所有 JD 内容统计信号命中数。满足 `category == "emerging"` 或 `signal_count >= 3` 的岗位作为候选。置信度 = `min(0.98, 0.68 + signal_count * 0.05 + 技能数 * 0.02)`。

- **`analyze_job_updates(job_id)`**：既有岗位能力更新。取该岗位最早和最晚批次的 JD，分别抽取技能并统计频次，计算：
  - `added`：当前批次有而基线批次无的技能
  - `removed`：基线批次有而当前批次无的技能
  - `strengthened`：两批次都有但当前频次更高的技能

- **`match_resume_to_job(job_id, resume_text)`**：人岗匹配。计算公式：`score = (covered_required / required总数) * 80 + min(covered_bonus * 4, 20)`。对缺失的必备技能（最多 5 个），从 LEARNING_PATHS 获取学习步骤。

#### `services/graph.py` — 图谱构建

使用 NetworkX 构建无向图，节点类型包括：

| 节点类型 | 前缀 | 说明 |
|---------|------|------|
| job | `job:` | 岗位节点 |
| skill | `skill:` | 技能节点 |
| skill_category | `category:` | 技能类别节点 |
| scenario | `scenario:` | 行业场景节点 |

边关系类型：

| 关系 | 权重 | 说明 |
|-----|------|------|
| required | 2 | 岗位 → 必备技能 |
| bonus | 1 | 岗位 → 加分技能 |
| belongs_to | 1 | 技能 → 技能类别 |
| applies_to | 1 | 岗位 → 行业场景 |

输出包含节点列表、边列表和图指标（节点数、边数、密度）。

#### `services/repository.py` — 数据访问层

封装了 4 个查询函数，所有查询通过 `database.py` 的 `fetch_all` / `fetch_one` 执行，自动将 JSON 字段反序列化为 Python 对象。

### 5.3 数据库初始化流程

`database.py` 的 `init_db(force)` 函数：

1. 建立 SQLite 连接（路径：`data/talent_graph.db`）
2. 若 `force=True`，先 DROP 三张表
3. CREATE TABLE IF NOT EXISTS 创建表结构
4. 若 jobs 表为空，从 `data/jobs.json` 和 `data/resumes.json` 导入全部数据
5. `decode_row()` 负责将 JSON 字段（core_responsibilities、required_skills 等）反序列化

应用启动时（`@app.on_event("startup")`）自动调用 `init_db()`。前端首次加载时调用 `POST /api/init` 强制重置。

## 6. 核心算法详解

### 6.1 技能抽取算法

```
输入: text (JD 或简历原文)
输出: [{name, category, evidence[], confidence}]

算法:
  1. 将 text 按 。；;\n 分句
  2. 对每个标准技能 S 及其别名列表 A:
     a. 在 text 中做大小写不敏感匹配，记录命中的别名
     b. 从分句中找出包含任何别名的句子（最多 3 条）作为证据
     c. 计算置信度: min(0.99, 0.72 + 0.08×证据数 + 0.04×命中别名数)
  3. 按置信度降序排列
```

**置信度设计逻辑**：基础分 0.72 保证只要有匹配就能被识别；每多一条证据 +0.08（鼓励有据可查）；每多一个别名命中 +0.04（鼓励多表述覆盖）。上限 0.99 留出人工校正空间。

### 6.2 新岗位发现算法

```
输入: 所有岗位列表 + 所有 JD 记录
输出: [{job_id, title, confidence, signal_count, ...}]

新兴信号集 = {Agent, RAG, 工具调用, 多智能体, 大模型, 向量数据库, 模型评测}

算法:
  对每个岗位 J:
    1. 汇总 J 的所有 JD 内容为一个文本
    2. 统计新兴信号命中数 signal_count
    3. 若 J.category == "emerging" 或 signal_count >= 3:
       纳入候选
       置信度 = min(0.98, 0.68 + signal_count×0.05 + 技能数×0.02)
  按置信度降序返回
```

### 6.3 既有岗位能力更新算法

```
输入: job_id
输出: {added[], removed[], strengthened[], summary}

算法:
  1. 获取该岗位所有 JD 记录，提取批次集合
  2. 若只有 1 个批次，返回全部技能作为 added（新兴岗位的初始能力固化）
  3. 取最早批次作为 baseline，最晚批次作为 current
  4. 分别抽取技能并统计频次（Counter）
  5. added = current 技能集 - baseline 技能集
  6. removed = baseline 技能集 - current 技能集
  7. strengthened = 交集中 current 频次 > baseline 频次的技能
```

### 6.4 人岗匹配算法

```
输入: job_id, resume_text
输出: {score, covered_required[], missing_required[], covered_bonus[], learning_path[]}

算法:
  1. 解析简历得到技能集合 resume_skills
  2. covered_required = 岗位必备技能 ∩ resume_skills
  3. missing_required = 岗位必备技能 - resume_skills
  4. covered_bonus = 岗位加分技能 ∩ resume_skills
  5. score = (len(covered_required) / len(required)) × 80
           + min(len(covered_bonus) × 4, 20)
  6. 对 missing_required 中前 5 个技能，查询 LEARNING_PATHS 获取学习步骤
```

**评分设计**：必备技能占 80 分（核心），加分技能最多占 20 分（上限封顶），总分不超过 100。

### 6.5 图谱构建算法

```
输入: 所有岗位数据
输出: {nodes[], edges[], metrics{node_count, edge_count, density}}

算法:
  初始化空无向图 G
  对每个岗位 J:
    1. 添加 job 节点
    2. 对 J.required_skills 中每个技能 S:
       - 添加 skill 节点（含 category 属性）
       - 添加 category 节点
       - 添加边 (job → skill, relation="required", weight=2)
       - 添加边 (skill → category, relation="belongs_to", weight=1)
    3. 对 J.bonus_skills 中每个技能 S:
       - 添加边 (job → skill, relation="bonus", weight=1)
    4. 对 J.industry_scenarios 中每个场景 SC:
       - 添加 scenario 节点
       - 添加边 (job → scenario, relation="applies_to", weight=1)
  计算图指标: node_count, edge_count, density
```

### 7.1 页面模块划分

前端采用单页应用（SPA）架构，四个功能模块通过顶部导航切换：

| matching | 人岗诊断 | 简历输入、目标岗位选择、匹配评分、技能缺口、学习路径、解析证据 |

### 7.2 数据加载流程

```
页面加载
  → POST /api/init (强制重置数据)
  → Promise.all([
      GET /api/dashboard,
      GET /api/graph,
      GET /api/discover,
      GET /api/resumes
    ])
  → 对每个岗位: GET /api/updates/{job_id}
  → 渲染
```

### 7.3 图谱可视化实现

图谱使用原生 SVG 渲染，布局算法为手动分层：

- 左侧：job 节点（x=120）
- 中左：skill 节点（x=430，交错偏移 ±18px 避免重叠）
- 中右：skill_category 节点（x=725）
- 右侧：scenario 节点（x=850）

节点交互：
- 点击节点高亮（红色描边 + 阴影）
- 关联边标红（stroke-width 增大）
- 右侧面板显示节点详情和相邻关系

边样式：
- `required`：绿色实线（stroke-width=2.3）
- `bonus`：紫色虚线
- `belongs_to`：蓝色实线
- `applies_to`：黄色实线

### 7.4 样式设计

- 全局使用 CSS 变量和渐变背景
- 卡片采用玻璃拟态风格（白色半透明背景 + 大圆角 + 阴影）
- 按钮采用渐变蓝色（`linear-gradient(135deg, #2f6df6, #6d5dfc)`）
- 评分环使用 `conic-gradient` 实现圆环进度
- 响应式断点：1100px（双栏→双栏缩小）、760px（单栏）
